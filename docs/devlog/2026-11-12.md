# 2026-11-12: CSP parser and clickjacking checks (roadmap step 3)

## Plan
1. Write a real CSP parser in `packages/core` that follows the CSP Level 3
   "parse a serialized CSP" algorithm, instead of the Python engine's
   `partition(" ")` shortcut.
2. Port `check_csp` and `check_framing` on top of it, keeping weights, scores and
   messages identical to Python.
3. Where the parser exposes a real bug in the Python logic, fix it in **both**
   engines and pin the new behaviour with a parity case.
4. Unit-test the parser on its own, then the checks.

## Built
- `packages/core/src/csp.ts`: `parseCsp()` returns a `Map<directive, sourceTokens[]>`,
  plus small helpers: `hasSource`, `hasSourcePrefix`, `findAnyOriginSource`,
  `effectiveScriptSources` (script-src → default-src fallback) and
  `neutralizesUnsafeInline`.
- `packages/core/src/checks/csp.ts`: `checkCsp()` and `cspProblems()` (the list of
  weaknesses, exported so the dashboard can show them one by one later).
- `packages/core/src/checks/framing.ts`: `checkFraming()` (CSP `frame-ancestors`
  first, then `X-Frame-Options`).
- Python engine (`cli-python/header_auditor/checks.py`): the same parser
  (`parse_csp`) and the same fixes. Five gaps the parser exposed, each now a parity case:
  - Tab-separated policies (`default-src<TAB>'none'`) were not parsed at all.
  - Keywords were case-sensitive, so `'UNSAFE-EVAL'` slipped through.
  - Hash sources (`'sha256-…'`) didn't count as cancelling `'unsafe-inline'`
    (only nonces did), so strong hash-based policies lost 7 points.
  - `https:` / `http:` / `https://*` in `script-src` weren't seen as "any origin".
  - `frame-ancestors 'self' *` passed, because only a lone `*` failed.
- `spec/parity/checks.json`: +28 cases (15 CSP, 13 clickjacking), 53 in total. Six of
  them fail against yesterday's Python code. That was checked on purpose: it shows the
  cases test real behaviour changes.
- Tests: 108 Vitest tests (was 59), 69 pytest tests (was 39). ESLint (security
  plugin, zero warnings), Prettier, `tsc`, bandit, and the secrets grep over the diff are
  all clean. `pnpm audit --audit-level=high` passes. One existing **moderate** advisory
  remains (minimatch through eslint, dev-only), and today's change didn't touch any
  dependencies.

## Design decisions worth explaining
- **Parse into a structure, then judge it.** The old code ran substring checks on the
  raw header (`"'unsafe-inline'" in script_src`). The new code separates *parsing*
  (spec-driven, tested alone) from *policy evaluation* (`cspProblems`). That split is
  why the bugs above became visible: once tokens exist, "is `*` one of the sources?"
  and "is `*` the whole value?" are obviously different questions.
- **Follow the browser's algorithm, not a guess at it.** A scanner that parses
  differently from the browser gives wrong answers in both directions. Two
  browser rules are copied exactly: the **first** duplicate directive wins, and invalid
  directive names are **skipped**, not errors. Directive names and keywords are
  case-insensitive, but nonce/hash *values* are not, so tokens are stored as sent and
  only compared in lowercase.
- **Why hashes, nonces and `'strict-dynamic'` cancel `'unsafe-inline'`.** CSP2+ browsers
  ignore `'unsafe-inline'` when a nonce or hash is present. Sites keep it only as a
  fallback for very old browsers. With `'strict-dynamic'`, CSP3 browsers also ignore
  host and scheme sources. That's why Google's recommended
  `script-src 'strict-dynamic' 'nonce-…' 'unsafe-inline' https:` grades as a pass,
  while `script-src 'self' https:` (any HTTPS host can serve your scripts, a classic
  CSP bypass) is now flagged.
- **`frame-ancestors` beats `X-Frame-Options`.** Browsers ignore XFO when an
  enforced CSP has `frame-ancestors`, so the check reads CSP first. A strict XFO can't
  rescue a `frame-ancestors *`. Report-Only policies never enforce `frame-ancestors`,
  so they're ignored here. An empty `frame-ancestors` list matches nothing, so it
  counts as `'none'`.
- **Fix the reference implementation instead of copying its bugs.** Yesterday's rule
  was "parity over improvements". Today shows the other half of it: a behaviour change
  is fine as long as it lands in *both* engines in the same push, with a parity case
  that would fail if either side drifted back.
- **Linear-time parsing on untrusted input.** Header values come from servers we don't
  control. The parser only uses `split` and anchored, non-backtracking regexes, and a
  test parses a 5,000-directive policy within a time budget, so a hostile header can't
  cause a ReDoS.

## How to try it
```bash
corepack enable && pnpm install
pnpm check                                       # lint + format + tsc + 108 vitest tests
pnpm --filter @header-auditor/core test csp      # parser + CSP/framing unit tests
cd cli-python && pytest -q                       # 69 tests, incl. the same parity cases
```

```ts
import { HeaderMap, checkCsp, checkFraming, parseCsp } from "@header-auditor/core";
parseCsp("default-src 'self'; script-src 'self' https:");
// Map { "default-src" => ["'self'"], "script-src" => ["'self'", "https:"] }
checkCsp(new HeaderMap({ "Content-Security-Policy": "default-src 'self'; script-src 'self' https:" }));
// { status: "warn", score: 11, detail: "script-src allows any origin (https:); object-src not restricted.", ... }
checkFraming(new HeaderMap({ "Content-Security-Policy": "frame-ancestors 'self' *", "X-Frame-Options": "DENY" }));
// { status: "fail", detail: "CSP frame-ancestors allows any origin (*).", ... }
```
