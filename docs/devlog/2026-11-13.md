# 2026-11-13: Remaining checks, scoring and grade (roadmap step 4)

## Plan

   information disclosure and cookie flags, keeping weights, scores and messages
   identical to Python.
2. Port the `Report` scoring: total score, percentage, letter grade, and the

  - **COOP with parameters**: `Cross-Origin-Opener-Policy: same-origin; report-to="coop"`

    token before `;` is compared now.
  - **Cookie attribute whitespace**: `SameSite = Lax` or `Secure ` (with spaces)
    weren't recognised. RFC 6265 §5.2 says attribute names are trimmed, so they

## Design decisions worth explaining
- **Rounding is part of the spec.** Python's `round()` uses *banker's rounding*
  (ties go to the even number: `round(12.5) == 12`), while JavaScript's
  `Math.round(12.5)` is 13. This isn't theoretical. A plain-HTTP site with no
  security headers earns 10 of 80 points = exactly 12.5%. So `roundHalfEven()`
  copies Python's rule, and a parity case pins it. It also uses **integer**
  arithmetic (quotient and remainder of `100 × earned / max`) rather than
  floating point, so a tie is detected exactly, never "almost 0.5".
- **Score over what applies.** The percentage is earned / *available* points.
  Checks that don't apply (HSTS over HTTP, cookies when none are set) return
  weight 0 instead of a free pass or a penalty. That way a site isn't punished for
  not setting cookies, and an HTTP site isn't rewarded for a header browsers
  would ignore anyway.
- **Internal type vs wire format.** The TypeScript `Report` uses idiomatic
  `statusCode` and also exposes `earned`/`maxScore` for the dashboard.
  `reportToJson()` produces exactly the Python `to_dict()` shape (`status_code`,
  no extras), so results from either engine can be stored side by side. The API
  layer will use the JSON form, and the code works with the typed one.
- **Parse headers the way the browser does.** Both fixes today come from the same
  idea as yesterday's CSP parser: a header has a grammar, and string equality on
  the raw value isn't that grammar. COOP is a structured-field token with
  optional parameters. Set-Cookie attributes are `;`-separated with trimmed,
  case-insensitive names. The cookie *value* is never searched for flags
  (`pref=Secure` doesn't count as `Secure`), and there's a test for that.
- **Keep Set-Cookie lines separate.** Cookie dates contain commas
  (`Expires=Wed, 21 Oct 2026 …`), so joining repeated headers with `, ` (what
  `fetch`'s `Headers.get` does) would corrupt them. `HeaderMap.getAll` returns
  every line, and a test checks a cookie with an `Expires` date next to two
  others.
- **Fail loudly on impossible input.** `roundHalfEven` throws on non-integers,
  negatives or a zero denominator, and `buildReport` rejects status codes outside
  100–599. Reports and their findings arrays are frozen, so a later pipeline step
  can't quietly change a grade.

## How to try it
```bash
corepack enable && pnpm install
pnpm check                                         # lint + format + tsc + 177 vitest tests
pnpm --filter @header-auditor/core test report     # new checks + scoring unit tests
pnpm --filter @header-auditor/core test parity     # all shared cases, incl. scoring.json
cd cli-python && pytest -q                         # 119 tests, same parity files
```

```ts
import { HeaderMap, buildReport, reportToJson, runAll } from "@header-auditor/core";
const headers = new HeaderMap({
  Server: "nginx/1.25.3",
  "X-Frame-Options": "SAMEORIGIN",
  "X-Content-Type-Options": "nosniff",
  "Set-Cookie": "connect.sid=abc; Path=/; HttpOnly",
});
const report = buildReport("https://localhost/", 200, runAll(headers, { isHttps: true }));
report.score; // 34
report.grade; // "F"
reportToJson(report); // same shape as `header-auditor --json`
```
