# 2026-11-10: Monorepo restructure (roadmap step 1)

## Built
- Moved the Python CLI (package, tests, `pyproject.toml`) into `cli-python/` with
  `git mv`, so file history follows the move. All 14 Python tests and bandit still pass.
- Turned the repo root into a **pnpm workspace** (`apps/*`, `packages/*`) with a shared
  strict `tsconfig.base.json`, ESLint flat config (typescript-eslint strict + type-aware
  rules + `eslint-plugin-security`), Prettier and `.editorconfig`.
- Scaffolded `packages/core` (the future TypeScript scan engine) with build/typecheck/test
  scripts and a Vitest smoke test, so the whole toolchain runs end to end before real
  checks land.
- CI now has two jobs: Python (3.9 + 3.12 matrix, pytest + bandit, run from `cli-python/`)
  and TypeScript (frozen-lockfile install, lint, format check, typecheck, Vitest,
  `pnpm audit --audit-level=high`).
- Committed `.env.example` (placeholders only); `.gitignore` blocks every other `.env*`.

## Design decisions worth explaining
- **Keep the Python CLI as its own sub-project instead of rewriting it.** It is a working,
  tested, zero-dependency tool. The TypeScript engine is a port that must reach parity,
  and the Python tests act as the specification for that port.
- **pnpm workspaces** give one lockfile and strict, non-hoisted `node_modules`: a package
  can only import what it declares, which catches missing dependencies that npm/yarn
  hoisting would hide. `packageManager` in `package.json` pins the exact pnpm version
  so CI and laptops resolve identically (`--frozen-lockfile` fails if they drift).
- **Strict TypeScript beyond `strict`:** `noUncheckedIndexedAccess` forces handling of
  missing keys (very relevant for HTTP headers, which may be absent) and
  `exactOptionalPropertyTypes` stops `undefined` sneaking into optional fields.
- **TypeScript pinned to 6.0.x, not 7.** typescript-eslint's type-aware rules only
  support TS < 6.1 today; using 7 would silently break linting. Pinning a tool to what
  its ecosystem supports is a deliberate trade-off, revisited later.
- **Security linting from day one** (`eslint-plugin-security`, `--max-warnings=0`). For
  example it flagged a `readFileSync` with a computed path in the first test; I replaced
  it with a typed JSON import rather than suppressing the warning.
- **Two separate CI jobs** so a Python failure and a TypeScript failure show up
  independently, with least-privilege `permissions: contents: read` and
  `concurrency` to cancel stale runs.

## How to try it
```bash
corepack enable && pnpm install
pnpm check                         # lint + prettier + tsc + vitest
pnpm test:py                       # Python suite from the root
cd cli-python && pip install -e ".[dev]" && pytest -q && bandit -q -r header_auditor
```
