# 2026-11-14: `scanUrl()` fetcher with SSRF guard (roadmap step 5)

## Plan
1. Add the engine's only network code in `packages/core/src/scan/`, kept apart
   from the pure checks.
2. Follow redirects by hand, one hop at a time, and validate every hop: scheme,
   credentials, IP literal, DNS answer.
3. Block private, loopback, link-local and reserved addresses unless
   `allowPrivate` is set. Do the check inside the socket's DNS lookup so DNS
   rebinding can't get around it.
4. One time budget covers the whole scan. Callers can also cancel with an
   `AbortSignal`. Every failure becomes a `ScanError` with a stable `code`.
5. Integration tests against a mock server on 127.0.0.1, with an injected
   resolver standing in for DNS.

## Built
- `scan/address.ts`: `isPrivateAddress()` checks addresses against the IANA
  special-purpose ranges (RFC 1918, CGNAT, loopback, link-local incl.
  `169.254.169.254`, TEST-NETs, multicast, `fc00::/7`, `fe80::/10`, …).
  `embeddedIpv4()` decodes IPv4-mapped, NAT64 and 6to4 addresses.
  `parseAllowList()` takes single IPs or CIDRs. `isAddressAllowed()` combines
  them into one policy.
- `scan/lookup.ts`: `createGuardedLookup()`, a `net.connect`-compatible
  `lookup` that resolves the host and refuses to connect if any answer is
  disallowed. The resolver can be swapped out (`Resolver` type), so tests use
  fixtures and step 8's DNS checks can reuse the same idea.
- `scan/scan-url.ts`: `scanUrl(url, options)` → `{ report, redirects }`, built on
  undici's `request` with a per-scan `Agent`. Options: `timeoutMs` (default
  10 s, max 120 s), `followRedirects`, `maxRedirects` (default 5, max 20),
  `allowPrivate`, `allowAddresses`, `resolver`, `userAgent`, `signal`. All of
  them are validated, so a bad option fails with `INVALID_OPTIONS`.
  `validateTarget()` is exported for the API to reuse on user input.
- `scan/errors.ts`: `ScanError` with codes `INVALID_URL`, `INVALID_OPTIONS`,
  `BLOCKED_SCHEME`, `BLOCKED_ADDRESS`, `DNS_FAILURE`, `TOO_MANY_REDIRECTS`,
  `REDIRECT_LOOP`, `TIMEOUT`, `ABORTED`, `NETWORK`.
- New dependency: `undici@^7` (runtime, `packages/core` only).
- Tests: 290 Vitest tests (was 177). The new `address.test.ts` has 75 and the
  new `scan-url.test.ts` has 38. pytest is unchanged at 119. ESLint (security
  plugin, zero warnings), Prettier, `tsc`, bandit and the secrets grep over the
  diff are all clean. `pnpm audit --audit-level=high` passes; the only advisory
  is still the known moderate dev-only one (minimatch via eslint).

## Design decisions worth explaining
- **What SSRF is and why a scanner has to guard against it.** Server-Side
  Request Forgery means making a server send requests for you. Once this
  scanner runs as a hosted service, users hand it URLs and it fetches them
  *from inside our network*. Without a guard, `http://169.254.169.254/latest/meta-data/`
  reads the cloud instance's credentials, and `http://10.0.0.5:6379/` pokes an
  internal Redis. So the default is deny: only public unicast addresses can be
  reached. `allowPrivate` exists for local development, and `allowAddresses`
  opens one known staging box without opening the whole LAN.
- **Check the address at connect time, not before (DNS rebinding).** The naive
  approach is to resolve the hostname, check the IP, then call `fetch(url)`.
  But `fetch` resolves the name *again*, and an attacker's DNS server can answer
  the first query with a public IP and the second with `127.0.0.1` (TTL 0).
  That's a time-of-check/time-of-use bug. The fix is to put the check inside
  the socket's own `lookup` callback (`Agent({ connect: { lookup } })`), so the
  address that gets validated is the exact address the socket connects to.
- **IP literals skip DNS, so they get their own check.** `net.connect` never
  calls `lookup` when the host is already an IP. So `validateTarget()` checks
  IP-literal hosts before connecting. It reads them from the WHATWG URL parser's
  normalised hostname, which already turns tricks like `http://2130706433/`,
  `http://0x7f.1/` and `http://[0:0:0:0:0:0:0:1]/` into `127.0.0.1`/`::1`.
  IPv6 forms that carry an IPv4 address inside (`::ffff:127.0.0.1`,
  `64:ff9b::a00:1`, `2002:7f00:1::`) are decoded and the inner address is
  checked too.
- **Reject the whole host on any bad record.** If a name returns one public
  and one private address, the scan fails. It doesn't quietly drop the bad
  record. Mixed answers are either a misconfiguration or an attack, and
  "connect to whichever one is allowed" would leave a race to exploit.
- **Redirects are followed by hand.** Automatic redirect-following re-checks
  nothing. A public page that answers `302 Location: http://10.0.0.1/` would
  sail through. Each hop goes through the same validation as the first URL:
  scheme allow-list (`file:`, `gopher:`, `ftp:` refused), no
  `user:pass@` credentials, address policy. On top of that there's a hop limit
  and loop detection. The chain comes back as `redirects`, so the dashboard
  can show "http → https → www".
- **Fail closed.** Anything that isn't a valid IP counts as private. A failed
  DNS lookup is an error, never a fallback. Every option has a range. The user
  agent is checked for CR/LF so it can't inject headers.
- **One deadline for the whole scan.** `AbortSignal.timeout(timeoutMs)` covers
  every hop together, and `AbortSignal.any` merges it with the caller's signal.
  undici's connect/headers/body timeouts are a second safety net. A server can't
  hold a worker longer than the budget by spreading delays across five
  redirects.
- **Stable error codes instead of messages.** The API and dashboard (steps 12+)
  need to show "blocked: private address" and "timed out" as different things,
  and store them. They branch on `ScanError.code`, never on message text, and
  error URLs never include credentials.
- **Tests never leave 127.0.0.1.** The mock server counts every request it
  gets. Tests for blocked targets assert that the counter didn't move, which
  proves the block happened *before* a connection was opened. "Internal" host
  names come from an injected resolver, not real DNS.

## How to try it
```bash
corepack enable && pnpm install
pnpm check                                          # lint + format + tsc + 290 vitest tests
pnpm --filter @header-auditor/core test scan-url    # integration tests (mock server on 127.0.0.1)
pnpm --filter @header-auditor/core test address     # SSRF policy unit tests
cd cli-python && pytest -q                          # 119 tests
```

```ts
import { scanUrl, ScanError } from "@header-auditor/core";

// Against your own local dev server (private targets need explicit opt-in):
const { report, redirects } = await scanUrl("http://127.0.0.1:3000/", { allowPrivate: true });
console.log(report.grade, report.score, redirects);

try {
  await scanUrl("http://169.254.169.254/latest/meta-data/");
} catch (err) {
  if (err instanceof ScanError) console.log(err.code); // "BLOCKED_ADDRESS"
}
```

## Next
Roadmap step 6: TLS check (protocol version, certificate expiry/issuer/hostname
match, weak ciphers) with a local self-signed test server. That also gives
`scanUrl` an HTTPS test path. Today's tests are HTTP-only, and https→http
downgrades in a redirect chain aren't flagged yet.

Known gaps to pick up later:
- The response body is drained and thrown away. Step 7 (mixed content) will
  need a bounded body read for HTML responses.
- There's no port allow-list yet (e.g. only 80/443 for hosted scans). Add it to
  the API's config with step 12.
- The Python CLI still follows redirects without an SSRF guard. That's fine for
  a local tool, but worth documenting in its README.
