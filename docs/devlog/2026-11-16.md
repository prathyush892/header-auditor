# 2026-11-16: HTTP→HTTPS redirect + mixed content (roadmap step 7)

## Plan
1. Teach `scanUrl()` to read the final page's HTML, bounded (never buffer an
   unbounded body), and only when the response is HTML.
2. Pure checks in a new `content/` module: HTML resource extraction, mixed
   content, redirect-chain downgrades, and grading of the http:// address.
3. A small network wrapper, `probeHttpsRedirect()`, that reuses `scanUrl()`
   so the SSRF guard, timeouts and redirect limits apply unchanged.
4. Score the new findings in their own `ContentReport` (like the TLS report),
   so the header score stays at parity with the Python CLI.
5. Integration tests against local http and https servers on 127.0.0.1.

## Built
- `content/html.ts`: `extractResources(html)` tokenizes with **htmlparser2**
  (new dependency, MIT) and returns every URL the page would load, classified as
  `blockable` (script, stylesheet/preload/icon `<link>`, iframe/frame, object,
  embed, track, `<base>`, `input type=image`, CSS `url()`/`@import` in `<style>` and
  `style=""`), `upgradeable` (`img` src/srcset, `audio`, `video` src/poster,
  `source`), or `form` (`form action`, `formaction`). Also returns the first
  `<base href>` and any `<meta http-equiv="Content-Security-Policy">`.
  `parseSrcset()` follows the HTML spec algorithm, so `img.jpg?w=1,2 100w` keeps its comma.
- `content/mixed-content.ts`: `findMixedContent()` resolves every reference
  (against `<base>` when present) and keeps the ones that end up `http:`,
  skipping localhost/loopback. `checkMixedContent()` (15 pts):
  - pass: https page, nothing insecure;
  - warn (10): only auto-upgraded media, or everything is covered by
    `upgrade-insecure-requests` (header or meta CSP; Report-Only doesn't count);
  - fail (0): blockable content, or a form posting to http that nothing upgrades;
  - info: http page or non-HTML response (not applicable, unscored).
- `content/redirects.ts`:
  - `checkRedirectChain()` (10 pts) fails on any https → http hop.
  - `analyzeHttpsRedirect()` (15 pts) grades what the http:// address does:
    301/308 to https on the same host passes; temporary redirect, different
    host, extra plain-http hops, or a broken https endpoint warn; serving
    content over http or never reaching https fails; nothing listening on
    port 80 is `info`.
- `content/probe-redirect.ts`: `probeHttpsRedirect(url, { httpPort, ...scanOptions })`.
  `httpVariant()` builds the http:// URL (same host and path, query dropped,
  port 80 unless the input was http:// or `httpPort` is given).
- `scanUrl()`:
  - new `maxBodyBytes` option (default 1 MiB, max 10 MiB, 0 = skip), validated
    before connecting. Only the final, non-redirect, HTML response is read;
    everything else is drained (64 KiB) as before.
  - result gains `content: ContentReport` (findings, score/grade, the list of
    insecure references, `upgradeInsecureRequests`, `bodyBytes`, `bodyTruncated`).
  - `ScanError` gains `redirects`: the hops followed before a failure.
  - exported helpers `parseContentType()` and `isHtmlResponse()`.
- Tests: 477 Vitest tests (was 387): 44 in `mixed-content.test.ts` and 14 in
  `redirects.test.ts` (pure fixtures), 32 in `content-scan.test.ts` (local
  http + https servers, cert minted at test time). pytest unchanged at 119.
  ESLint (security plugin, zero warnings), Prettier, `tsc`, bandit and the
  secrets grep are clean. `pnpm audit` reports one pre-existing moderate
  advisory (minimatch via eslint, dev-only); nothing high or critical.

## Design decisions worth explaining
- **Why mixed content matters.** HTTPS protects a page only if *everything*
  it loads is also protected. One `<script src="http://...">` lets anyone on
  the network rewrite that script and run code in the secure origin, which
  is a full compromise of the page. A form that posts to http sends the
  password in clear text. So the check grades by *what the browser would do*,
  following W3C Mixed Content Level 2: scripts, styles and frames are
  "blockable" (fail: real risk in old browsers, broken page in new ones);
  `img`/`audio`/`video` are auto-upgraded by modern browsers (warn: no leak,
  but the image breaks if the CDN has no HTTPS).
- **A real tokenizer, not regex.** Regexes over HTML get fooled by comments
  (`<!-- <script src=http://...> -->`), strings inside `<script>`, and
  entity encoding (`&#104;ttp://` is `http://` to the browser). htmlparser2
  tokenizes like a browser; tests pin all three cases. The only regexes left
  are for CSS `url()`/`@import`, with bounded quantifiers so they can't backtrack
  badly (ReDoS) on hostile input.
- **Resolve URLs exactly like the browser.** Relative URLs on an https page
  are https, so they're never flagged; protocol-relative `//cdn` inherits
  https; but `<base href="http://...">` turns *every* relative URL into http,
  so the base itself and everything under it is reported.
- **Localhost isn't mixed content.** The Secure Contexts spec treats
  `localhost` and loopback IPs as "potentially trustworthy", and browsers
  don't block them. Flagging a dev server's `http://localhost:3000/hmr.js`
  would be a false positive.
- **`upgrade-insecure-requests` is a mitigation, not a fix.** It makes the
  browser rewrite http subresources to https, so blockable content drops from
  fail to warn. It only upgrades *same-origin* navigations, so a form posting
  to another host over http still fails. Report-Only CSP enforces nothing and
  is ignored.
- **Bounded body read.** The scanner fetches user-chosen URLs, so the target
  may be hostile. The body is read chunk by chunk and the stream is destroyed
  at `maxBodyBytes`; memory never exceeds the limit. If truncated, the finding
  says only part of the page was inspected rather than claiming a clean pass.
  Non-HTML responses aren't read at all; a missing Content-Type *is* read,
  because browsers sniff it as HTML.
- **Separate score for content checks.** The header score is pinned to the
  Python CLI by the parity fixtures. Mixing new checks into it would break that
  contract, so (like TLS) these findings get their own `ContentReport`. The
  worker in step 15 can combine the sections.
- **What a good HTTP→HTTPS redirect looks like.** The first hop should be
  a *permanent* (301/308) redirect to https on the *same host*. Permanent so
  browsers and caches remember it; same host so the browser actually visits
  `https://example.com` and gets that host's HSTS header (going straight to
  `https://www.example.com` means `example.com` never gets HSTS). Every extra
  plain-http hop is one more request an attacker can intercept (SSL stripping).
  Nothing listening on port 80 is `info`, not a failure: nothing leaks, it's
  just less convenient.
- **Reuse the guarded fetcher.** `probeHttpsRedirect()` is a thin wrapper around
  `scanUrl()`, so the redirect chain gets the same SSRF re-validation on every
  hop. A redirect to `https://10.0.0.1/` is re-thrown as `BLOCKED_ADDRESS`
  (a policy decision about the target), not graded as site behaviour.
- **Errors carry the chain.** If the http address redirects correctly but
  the https endpoint is down, the redirect still happened and should be graded.
  `ScanError.redirects` keeps the hops followed before the failure, which the
  API can also show to users ("failed at hop 3").

## How to try it
```bash
corepack enable && pnpm install
pnpm check                                               # lint + format + tsc + 477 tests
pnpm --filter @header-auditor/core exec vitest run mixed-content redirects content-scan
cd cli-python && pytest -q                               # 119 tests
```

```ts
import { checkMixedContent, probeHttpsRedirect, scanUrl } from "@header-auditor/core";

// Pure: grade a snippet of HTML without any network.
const { finding } = checkMixedContent({
  pageUrl: "https://app.test/",
  html: '<script src="http://cdn.test/lib.js"></script>',
});
console.log(finding.status, finding.detail); // fail Active mixed content: ...

// Against your own local servers (private targets need explicit opt-in):
const { content } = await scanUrl("https://127.0.0.1:8443/", { allowPrivate: true });
const redirect = await probeHttpsRedirect("https://127.0.0.1:8443/", {
  allowPrivate: true,
  httpPort: 8080,
});
console.log(content.grade, redirect.finding.status);
```

Known gaps to pick up later:
- Only the initial HTML is inspected. Resources added by JavaScript, and
  `url()`s inside external stylesheets, aren't seen; that would need a
  headless browser.
- `<meta http-equiv="refresh" content="0;url=http://...">` downgrades and
  insecure links (`<a href="http://">`) aren't flagged; neither is mixed content
  loaded through `@font-face` in external CSS.
- Charset detection uses only the Content-Type header (falls back to UTF-8),
  not `<meta charset>`. Fine for URLs, which are ASCII.
- The `minimatch` moderate advisory (dev dependency via eslint) clears when
  eslint bumps its dependency.
