# 2026-11-19: Subresource Integrity check (roadmap step 10)

## Plan

1. A pure module, `content/sri.ts`, next to the mixed-content check: extract
   `<script src>` and `<link>` stylesheets/preloads from the HTML the scan
   already read, keep the third-party ones, and inspect their `integrity` and
   `crossorigin` attributes.
2. Parse `integrity` the way browsers do, so "has an attribute" never gets
   confused with "is protected".
3. Grade it as a third finding in the content report (10 pts).
4. Unit tests on HTML fixtures; one integration test over a real socket that
   proves no subresource is ever requested.

## Built

- `content/sri.ts`
  - `parseIntegrity(value)`: splits the attribute on whitespace, accepts
    `sha256`/`sha384`/`sha512` tokens, ignores `?options`, and checks that the
    digest is base64 (or base64url) of the right length (32/48/64 bytes).
    Unknown algorithms (`md5`, `sha1`), placeholders (`sha384-HASH_GOES_HERE`)
    and truncated digests are rejected, exactly the cases where a browser
    silently loads the file unchecked.
  - `isFirstPartyHost(host, pageHost, extra)`: the page's host or a subdomain
    of it (a leading `www.` is ignored), plus an explicit `firstPartyHosts`
    list.
  - `findSriReferences(html, pageUrl, firstPartyHosts)`: htmlparser2 tokenizer;
    covers `<script src>` (JS types and `module`, not JSON/template/importmap
    data blocks), `<link rel=stylesheet>` (incl. "alternate stylesheet"),
    `rel=modulepreload`, `rel=preload as=script|style`. Resolves against
    `<base href>`, skips `data:`/`blob:`, capped at 1000 references. Each
    reference gets a status: `protected`, `missing`, `invalid` or `no-cors`.
  - `checkSubresourceIntegrity()` (10 pts):
    - pass (10): no third-party scripts/stylesheets, or all pinned and CORS-fetched;
    - warn (8): hashes valid but `crossorigin` missing (the browser blocks them);
    - warn (5): scripts pinned, some stylesheets not;
    - fail (0): any third-party script without a usable hash;
    - info: non-HTML response.
- `content/report.ts`: `ContentReport` gains the SRI finding (third, after
  redirect chain and mixed content), a `subresourceIntegrity` reference list,
  and an optional `firstPartyHosts` input.
- Tests: 786 Vitest tests (was 732): 52 new in `sri.test.ts`, plus an
  integration test in `content-scan.test.ts` that serves a page over https on
  127.0.0.1 and asserts the server only saw the request for the page itself.
  pytest unchanged at 119. ESLint (security plugin), Prettier, `tsc`, bandit
  and the secrets grep are clean. `pnpm audit --prod`: no vulnerabilities;
  the dev-only `minimatch` (via eslint) remains.

## Design decisions worth explaining

- **Why SRI matters.** A third-party `<script>` runs with the full power of
  your page: it can read the DOM, cookies without `HttpOnly`, and anything
  the user types. HTTPS only proves the bytes came from the CDN, not that
  the CDN is serving what you reviewed. Real incidents (the polyfill.io
  domain takeover in 2024, the British Airways Magecart skimmer in 2018) were
  exactly this. With `integrity="sha384-..."` the browser hashes the file and
  refuses to run it on mismatch, so a compromised CDN breaks the page instead
  of owning it.
- **Parsing like a browser, not like a grep.** The dangerous failure is a
  site that *looks* protected: `integrity="sha384-TODO"` or `md5-...` is
  silently ignored by browsers and the file loads unchecked. So an attribute
  with no usable hash is graded the same as no attribute, and the detail says
  "unusable integrity value" so the owner knows why. Unknown tokens next to a
  valid one are ignored (the browser uses the valid one), so the parser does
  the same.
- **`crossorigin` is part of SRI.** A cross-origin script fetched without
  `crossorigin` is an *opaque* response; the browser can't read it to hash
  it, so it blocks it. That's safe but broken, hence a mild warn (8) rather
  than a fail. Module scripts and `modulepreload` are always fetched in CORS
  mode, so they don't need the attribute; the check knows that instead of
  producing false warnings.
- **Scripts fail, stylesheets warn.** A tampered script is code execution.
  A tampered stylesheet can deface the page or leak data through CSS
  selectors (attribute-selector keyloggers), which is real but smaller, so
  unpinned CSS costs half the points rather than all of them.
- **Who counts as third-party, without a public-suffix list.** Guessing the
  registrable domain by "last two labels" is wrong for `example.co.uk` and
  would treat every `.co.uk` site as first-party. Instead the rule is
  conservative: the page's own host and its subdomains (with `www.` ignored)
  are first-party; anything else is third-party unless listed in
  `firstPartyHosts`. A wrong guess here costs a few points, never a missed
  finding.
- **Presence, not correctness.** The scanner never downloads the scripts
  (the integration test asserts it), so it can't confirm the hash matches.
  That's a deliberate scope choice: the browser already verifies the match on
  every load; what it can't do is notice the attribute was never there.
- **Limits stated, not hidden.** Scripts injected at runtime (tag managers,
  `document.createElement("script")`) don't appear in the HTML, so they
  aren't seen. A CSP `script-src` allow-list is the control for those.

## How to try it

```bash
corepack enable && pnpm install
pnpm check                                                # lint + format + tsc + 786 tests
pnpm --filter @header-auditor/core exec vitest run sri    # just today's tests
cd cli-python && pytest -q                                # 119 tests
```

```ts
import { checkSubresourceIntegrity, parseIntegrity } from "@header-auditor/core";

parseIntegrity("sha384-TODO"); // [] -> the browser would ignore it

const { finding, references } = checkSubresourceIntegrity({
  pageUrl: "https://www.example.test/",
  html: `<script src="https://cdn.example-cdn.test/lib@1.2.3/lib.min.js"></script>
         <script src="https://static.example.test/app.js"></script>`,
});
finding.status; // "fail": the CDN script has no integrity; static.example.test is first-party
references.map((r) => r.status); // ["missing"]
```
