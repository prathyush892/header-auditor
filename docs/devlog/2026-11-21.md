# 2026-11-21: API skeleton (roadmap step 12)

## Plan

1. New workspace app `apps/api` (Fastify 5, zod 4), consumed later by auth,
   sites and the scan queue.
2. `loadConfig()`: read only known env vars, validate with zod, fail fast
   with messages that name the variable but never echo its value.
3. Structured JSON logging with request ids, credential redaction and no
   query strings in logs.
4. One error envelope for every failure; 5xx never leak internals.
5. Liveness and readiness probes with injectable dependency checks.
6. `buildApp()` separated from `listen()` so tests use `app.inject()`;
   graceful shutdown on SIGTERM/SIGINT.

## Built

- `apps/api/src/config.ts`: zod schema for `NODE_ENV`, `LOG_LEVEL`,
  `API_HOST` (default `127.0.0.1`), `API_PORT`, `API_TRUST_PROXY`,
  `API_BODY_LIMIT_BYTES`, `API_REQUEST_TIMEOUT_MS`, `API_SHUTDOWN_TIMEOUT_MS`,
  `API_READINESS_TIMEOUT_MS`. Returns a frozen camelCase `ApiConfig`, or
  throws `ConfigError` listing every problem at once.
- `apps/api/src/logger.ts`: pino options (Fastify's built-in logger):
  `service: "api"`, ISO timestamps, `[REDACTED]` for `authorization`,
  `cookie`, `x-api-key`, `proxy-authorization`, `set-cookie` and any
  `*.password` / `*.passwordHash` / `*.token` / `*.secret` field; request
  serializer logs method, path (query stripped) and remote address only.
  `generateRequestId()` reuses a safe `X-Request-Id` or makes a UUID.
- `apps/api/src/errors.ts`: `AppError(status, CODE, message, {details, cause})`,
  a pure `classifyError()` and the Fastify error and 404 handlers. Response
  shape: `{ "error": { code, message, requestId, details? } }`.
- `apps/api/src/health.ts`: `GET /health` (liveness, no dependencies) and
  `GET /health/ready` (runs registered `HealthCheck`s in parallel, each with
  a timeout and an `AbortSignal`; 503 if any fail).
- `apps/api/src/app.ts`: `buildApp({ config, healthChecks, logger })`. Body
  limit, request timeout, `trustProxy` and `return503OnClosing` from config;
  `onRequest` hook sets `X-Request-Id`, `Cache-Control: no-store` and a
  baseline of security headers (`nosniff`, `default-src 'none';
  frame-ancestors 'none'`, `no-referrer`, CORP `same-origin`).
- `apps/api/src/server.ts`: `start()` and `createShutdown()` (idempotent,
  forces `exit(1)` if `app.close()` exceeds the timeout). A bad config
  prints the problems to stderr and exits 1 before binding a port.

## Design decisions worth explaining

- **Build vs listen.** `buildApp()` returns a configured instance without a
  socket. `app.inject()` pushes a fake request through the real lifecycle
  (hooks, parsing, validation, error handler, serialization), so tests are
  fast, parallel and never fight over ports. One test still binds
  `127.0.0.1:0` to prove the real server path works.
- **Fail fast on config, and say exactly what's wrong.** A typo'd
  `API_PORT` should crash at boot, not surface as a weird bind error. All
  issues are reported together so you fix them in one pass. Values are
  never echoed: later steps put secrets in env vars, and config errors end
  up in CI logs.
- **Empty means unset; "yes" is an error.** `API_PORT=` in a `.env` file uses
  the default instead of coercing to port 0. Booleans accept only
  true/false/1/0: silently reading `API_TRUST_PROXY=yes` as `false` is the
  kind of bug you only find in production.
- **Loopback by default.** Same principle as the compose file: exposing the
  API to the network is an explicit `API_HOST=0.0.0.0` (containers set it).
- **`trustProxy` is off by default.** When on, Fastify believes
  `X-Forwarded-For`. That's required behind a proxy, but without one any
  client could spoof its IP, which would defeat the login rate limiter
  coming in step 13.
- **Error envelope: 4xx explain, 5xx hide.** Clients and the dashboard
  branch on a stable `code`, not on message text. For unexpected errors the
  client gets "Internal Server Error" plus the request id; the stack trace
  goes to the log under the same id. Leaking `ECONNREFUSED 10.1.2.3:5432`
  would hand an attacker a map of the internal network.
- **Request ids, validated.** Accepting an upstream `X-Request-Id` lets one
  request be traced across proxy and API, but a raw header in logs is an
  injection vector (newlines can forge log lines). Only `[A-Za-z0-9._:-]{1,64}`
  is reused; anything else gets a fresh UUID.
- **Logs never hold credentials.** Redaction covers auth headers and common
  secret field names even if a future route logs `request.headers` or a
  request body (there are tests for exactly that careless case). Query
  strings are dropped from logged URLs because password-reset and
  verification links carry tokens there.
- **Liveness vs readiness.** If `/health` checked the database, a database
  blip would make the orchestrator restart every healthy API container.
  Liveness only proves the process answers; readiness checks dependencies
  and pulls the instance from the load balancer instead. Each check has a
  timeout (a hung connection must not hang the probe) and receives an
  `AbortSignal` to cancel its work. Readiness responses say `ok`/`fail` per
  check only; details go to the log since the endpoint is unauthenticated.
- **Graceful shutdown.** `app.close()` stops accepting connections, lets
  in-flight requests finish, and runs `onClose` hooks (where the DB pool and
  queue will be closed). New requests during drain get 503
  (`return503OnClosing`). A timer forces exit if draining hangs, so
  `docker stop` doesn't wait for SIGKILL.
- **Defense-in-depth defaults.** 1 MiB body limit (413 above it), 30 s
  request timeout (slow-loris), Fastify's JSON parser rejecting
  `__proto__` keys (prototype pollution, tested), a 404 that doesn't reflect
  the path, and a strict CSP/nosniff on a JSON-only API. helmet replaces the
  hand-rolled headers in step 24.
- **Lint as a design tool.** `eslint-plugin-security` flagged a host regex
  as potentially catastrophic-backtracking and dynamic object keys as
  injection sinks. Rather than disabling the rules, the code now validates
  labels with simple checks and builds objects with `Object.fromEntries`.

## How to try it

```bash
corepack enable && pnpm install
pnpm --filter @header-auditor/api test          # today's 126 tests
pnpm --filter @header-auditor/api build
API_PORT=3001 node apps/api/dist/server.js       # JSON logs on stdout
curl -i http://127.0.0.1:3001/health
curl -i http://127.0.0.1:3001/health/ready
curl -i -H 'x-request-id: my-trace-1' http://127.0.0.1:3001/nope   # JSON 404, same id echoed
API_PORT=abc node apps/api/dist/server.js        # fails fast: "API_PORT: must be a whole number"
```

```ts
import { buildApp, loadConfig, AppError } from "@header-auditor/api";

const app = await buildApp({
  config: loadConfig(),
  healthChecks: [{ name: "database", check: async () => void (await prisma.$queryRaw`SELECT 1`) }],
});
app.get("/boom", () => {
  throw new AppError(409, "SITE_EXISTS", "Site already added");
});
```
